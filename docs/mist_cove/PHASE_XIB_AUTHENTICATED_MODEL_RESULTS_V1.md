The selected original P3B raw_context seed123 model passed byte authentication, restricted CPU parsing, exact named-state verification, construction checks and trained-adapter verification. This resolves the earlier loading block for this specific artifact. It does not establish physiological validity or reproduce its entire training trajectory.

Its original named-state digest matches `1b308f3fc38af22609d2043b0988998b1a193c6d4ace73ac84382bb17e1a4c6d` before and after model construction. No historical weight was rewritten.

The loader pins path components, rejects symlinks/nonregular files/hardlinks, applies bounded read-only snapshots and checks descriptor/path identity and modification metadata. Hash comparison precedes parsing. Actual restricted parsing used a separate CPU environment with PyTorch2.10.0+cpu, default serialization globals only, `weights_only=True`, CPU mapping and bounded archive checks. The old2.5.1 environment was not used to deserialize this checkpoint. Security review considered the [≤2.5.1 weights-only vulnerability](https://github.com/pytorch/pytorch/security/advisories/GHSA-53q9-r3pm-6pq6) and the [≤2.9.1 vulnerability fixed in2.10](https://github.com/pytorch/pytorch/security/advisories/GHSA-63cw-57p8-fm3p). This is a restricted authenticated-artifact workflow, not a proof that arbitrary checkpoints are safe or a general hostile-code sandbox.
